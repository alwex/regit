Releases

A release branch (release-<version>) gathers the features destined for the next version. When finished, it is merged into stable, tagged, and cleaned up.

Note

Only one release branch can exist at a time.

Start a release

ArgumentRequiredDescription
versionoptionalTarget version in semver (e.g. 1.2.0). Validated to be valid semver and greater than the latest tag.

When a version is given it is validated and the release-<version> branch is created from the latest tag.

When no version is given, regit opens an interactive prompt to pick the next version — Minor, Patch, or Major — computed from the latest tag. Choosing Major asks for an extra confirmation before continuing.

Prerelease versions are supported (e.g. regit release start 1.2.0-beta.1).

Open an existing release

If a release branch already exists, release start checks it out and warns you (Release already exists release-<version>) instead of creating a new one — even if you pass a different version. The start hooks still run, with origin: 'local' or 'remote'.

Release status

Shows the open release and the features merged into it, each flagged [merged] or [in progress].

Add features to a release

Add a single feature

Add multiple features

With no feature name, regit prompts an interactive multi-select of the available feature branches.

Either way, regit checks out the open release, merges each feature (origin/feature-<name>) with --no-ff, then pushes the release branch.

Commits outside features

You can also commit directly on the release branch (a last-minute fix, a version bump, a changelog) and push it with regit release push. These commits ship with the release; they are simply not listed as features. A release can even contain no feature at all (hotfix).

Push a release

Shorthand for pushing the current release branch to the remote. You must be on a release branch.

Finish a release

In order, regit:

  1. checks that every feature in the release is fully merged and up to date — otherwise it refuses (release status shows the [in progress] ones; re-add them);
  2. checks out the release branch and runs preReleaseFinish, then getTagMessage;
  3. pushes the release branch and merges it into stable;
  4. creates the annotated tag v<version> (message from getTagMessage, by default [regit] v1.2.0. (feature-a,feature-b)) and pushes stable and the tag;
  5. deletes the release branch and the features it included, locally and on origin;
  6. runs postReleaseFinish.

Caution

release finish changes stable on origin, pushes a tag and deletes the release and feature branches for everyone. Check regit release status first.

Remove a release

Deletes the open release branch (locally and on the remote). If you are currently on it, regit switches you back to stable first.

Hooks

CommandHooks
release startpreReleaseStart / postReleaseStart — also when the release is already open, and for preview release (context.trigger)
release addpreReleaseAdd / postReleaseAdd, with the features being merged
release finishpreReleaseFinish (on the release branch: commit a changelog there and it ships), getTagMessage (the tag message), postReleaseFinish (with the shipped features, the stable commit and the deleted branches)
